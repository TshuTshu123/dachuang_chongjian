# 原始数据与 PLY 输入选择说明

本文说明多视角 RAW 比单个合成 PLY 增加了什么、目前哪些收益已有证据，以及后续应保留哪些输入。以当前项目代码和这次实际导出为准，技术细节只保留与使用有关的部分。

## 1. 先说明本次数据的对应关系

本次完整 RAW 清理前位于 `data_raw/raw(2)/raw/`。经用户确认，它**不是现有 data 中那几份 PLY 对应的采集**，因此仅作为独立样例，不再认定它对应 export_00004 或“第四组”。2026-11-04 已按用户要求删除这批错误样例的原始文件、融合点云、试验模型、图片和检查结果；本文保留数据用途说明与清理前核验过的统计，等待下一批正确数据。

这意味着：可以比较这批 RAW 自身补色前后的效果，但不能用它与原来不同采集的模型比较，得出“RAW 让脸部或手部重建提升了多少”的结论。之后做正式对比，需要同一次采集、同一帧的 RAW 和合成 PLY。

本次目录包含：

| 数据 | 实际数量或内容 |
| --- | --- |
| 逐路 PLY | 18 份，共 285,055 个点，含坐标、法线和颜色 |
| 彩色 PNG | 36 张，每路两张，均为 2448 × 2048 |
| 相机参数 JSON | 36 份，每路 Primary、Secondary 各一份 |
| 变换和图像关系 TXT | 36 份，每路各两份 |
| 裁剪参数 CFG | 18 份 |
| 数据量 | 约 534 MiB，其中图片约 517 MiB |

这里的 RAW 是“一整套逐路导出文件”的简称，不是相机传感器的单个 `.raw` 照片文件。文件夹 `1、2、…、24、25` 表示不同数据流，`00000` 是导出的帧号，均不表示项目里 export_00000 的模型编号。

## 2. 相比一个合成 PLY，真正多了什么

项目原来的 data PLY 是已经合并的带颜色点云。它保留了“点在哪里、是什么颜色”，但通常已经失去“这个点来自哪个视角、那一路能否拍到它、照片的哪个像素对应它”等信息。

| 新增信息 | 能带来的作用 | 当前证据或进度 |
| --- | --- | --- |
| 每一路独立点云及来源 | 分辨多个视角是否一致；有机会分别去噪、筛掉差的观测，再融合 | 已按逐路变换矩阵对齐；各路抽样跨视角最近距离中位数约 1.7～3.3 mm。这是重叠一致性指标，不是真实测量误差 |
| 点云与彩色相机的对应关系 | 判断某个黑点是不是根本没有拍到颜色，再从其他有效视角补色 | **本轮已验证有明显收益** |
| 原始彩色照片 | 后续可尝试更清晰的颜色投影、面部外观和纹理贴图 | 当前只使用主照片检验投影及判断有效取色范围；尚未实现完整照片纹理融合 |
| 相机位置、朝向和原始法线 | 后续可用拍摄方向辅助法线定向，按视角可靠程度融合 | 合并点云时已统一原始法线的可见侧；本次网格重建仍使用原来的几何法线重估流程，尚未证明几何提升 |
| 裁剪范围和坐标变换信息 | 确认单位、统一坐标，帮助排除背景 | 本次读取了毫米单位和逐路变换；尚未自动应用裁剪配置中的物体变换和裁剪范围 |

多路点云不等于一定比合成 PLY 点数更多、表面更细。合成 PLY 可能已经使用过这些观测；RAW 的主要优势是**保留来源，使我们能重新判断哪些观测可靠**。

## 3. 本轮补色到底改善了什么

先把 18 路点云变换到同一坐标系，再利用相机参数判断每个点是否落在本路主照片的有效范围内。

对于“投影到照片范围外、且颜色近乎纯黑”的点，查找其他有效视角中距离较近、表面方向相近的点，将它的已有颜色补过来。当前最大距离是 8 mm，法线方向相似度要求大于 0.7；没有可靠邻点就保留原色。

**当前实际填入的颜色来自其他视角 PLY 的有效顶点色。PNG 用于判断和校验取色是否有效，还没有对所有照片做逐像素融合，也没有生成 UV 纹理。** 第二张 RGB 照片目前只做完整性检查和预览，尚未参与补色。

| 同一批 RAW 内的检查 | 结果 |
| --- | ---: |
| 原始点云中近乎纯黑的点 | 23,310 |
| 投影范围外的近乎纯黑点，作为候选 | 23,185 |
| 找到合适邻点进行补色的点 | 21,698，约占候选的 93.6% |
| 最终同一网格上近乎纯黑顶点，补色前 → 后 | 12,322 → 975，减少约 92.1% |

“近乎纯黑”在此指 RGB 三个通道均不超过 1/255。统计减少不代表每个点都恢复了真实颜色，邻近颜色仍是近似。它也不表示消除了所有亮暗问题。

对照图使用完全相同的网格、视角和光照，只改变颜色，因此能隔离补色的影响。补色步骤不移动点，也不改变模型形状。相机视野内的黑色仍可作为正常颜色保留，不会仅因颜色暗就被统一改亮。

上述统计来自清理前的原始检查报告和同网格颜色对照。对应图片、JSON 与试验 PLY 均已删除，本文不再保留失效下载链接。这一结果说明该方法在独立样例上有效，后续仍需在正确的配套数据上复测。

### 下身为什么仍有遗漏

剩余问题需要分开看：

- **颜色缺失**：其他视角也没拍到，或附近没有通过距离和方向检查的有效颜色时，当前方法会留下黑点。裤子、头发和阴影本身也可能是真实深色。
- **几何缺失**：没有采到表面点的位置，补色不能补出三维表面。试验中曾出现大块 Poisson 外扩；增加 12 mm 观测距离约束后去掉了明显外扩，但仍有局部孔洞。
- **照片融合尚未完成**：第二路 RGB、遮挡判断、多视角曝光差和照片纹理还没有完整利用。

因此，本轮可以确认“缺色黑点处理有改善”，暂不能确认“人体几何已经比单 PLY 更好”。12 mm 外扩约束也只是试验值，可能删掉本就缺少观测的真实表面，不作为所有数据的统一最佳参数。

## 4. 哪些参数可以放进代码，哪些必须跟着数据读

应当把“读取和使用这些参数的逻辑”加入代码，而不是把某次相机的具体数值抄成所有模型的常量。

| 参数或文件 | 在项目里的用途 | 使用原则 |
| --- | --- | --- |
| PLY 的 XYZ、RGB、法线 | 几何观测、颜色来源、表面方向 | 每一路单独读取，保留来源；法线仍需检查 |
| `*_transform.txt` | 把该路点云变换到共同坐标系 | 本次已使用；不能再对已经合成到共同坐标系的 PLY 重复应用 |
| Primary JSON 的 `F`、`C`、宽高、畸变 | 将三维点对应到照片位置，判断是否在有效视野内 | 本次已使用；按本路标定读取，不写死焦距、中心点和畸变数值 |
| Primary JSON 的 `rotation`、`translation` | 点云坐标与相机坐标之间的关系 | 本次已使用；必须核验变换方向、单位和轴方向，不能把所有矩阵都当成同一种含义 |
| Secondary JSON、`*_PhotogrammetryInfo.txt` | 为另一相机、另一照片建立对应关系 | 保留，后续核验后接入；本轮没有完整使用这条投影链 |
| CFG 的 `Units` | 确认毫米或米 | 本次明确为 mm；代码里的毫米阈值必须与输入单位一致 |
| CFG 的圆柱半径、高度、物体变换、切平面 | 可能用于裁剪或坐标整理 | 不是人体真实尺寸，也不是去噪强度；不能照搬本次 700 mm、2200 mm 或位置矩阵到所有模型 |
| 体素大小、去噪轮数、Poisson 深度、补色距离等 | 控制我们自己的处理方法 | 属于算法配置，可以复用默认值并按新数据验证；它们与相机标定是两类参数 |

同一套设备没有移动且标定未改变时，部分相机参数可能可以复用。但仍建议随每批数据保存一份配套标定，并核对标定版本或文件哈希；不能只凭“还是那台设备”就认定参数完全相同。

本次投影还涉及矩阵取逆、XY 轴符号和畸变系数次序。代码已经用各路已有点颜色与照片颜色作了一致性检查，当前 18 路通过。此约定适用于本次核验的导出格式，不代表其他格式或版本也能直接套用；检查不通过的路不参与本轮补色。

## 5. 以后到底只要 PLY，还是要 RAW，还是都要

**建议同时支持两种输入；能取得配套数据时，优先保留“同次同帧的 RAW + 合成 PLY”。**

| 能拿到的数据 | 适合的工作 | 能力限制 |
| --- | --- | --- |
| 只有一个合成 PLY | 沿用现有去噪、重建、法线与局部颜色处理 | 能继续运行，但很难判断黑点来自真实材质还是某路取色失败，也无法重新选择观测视角 |
| 完整 RAW | 自行对齐、处理来源可靠性、补色，再重建 | 足够作为独立重建输入；处理步骤更多，当前仍处于试验阶段 |
| 同次同帧 RAW + 合成 PLY | 既能开发新方法，又能与原结果公平对照 | **最推荐**；合成 PLY 方便检查和回退，RAW 保留后续优化空间 |

正式入口 run.py 已支持自动选择。它在 `data_raw/00001/` 或 `data_raw/export_00001/` 查找对应数据流，支持数据流目录直接放在编号下，或再套一层 `raw/`、`raw2/` 等目录。自动选择要求只有一份候选采集和一个完整帧，并逐点核对坐标与 RGB。找不到配套数据、参数不完整或校验未通过时，使用单 PLY 的颜色处理，原因写入 `report.json` 的 `raw_color`。

### 下次取数据的最小清单

选择同一次采集中的一个完整帧即可，暂时不需要导出整段所有帧。保留：

1. 每一路 PLY，尽量保留法线和颜色。
2. 对应的两路彩色图片，保持原始尺寸和路号、帧号。
3. 全部配套 JSON、transform、PhotogrammetryInfo、裁剪配置。
4. 同次同帧的合成 PLY，作为对照；能取得最终网格时也可额外保留，但它不能替代逐路点云。
5. 采集编号、帧号、时间戳或原始帧映射、单位、标定版本等对应信息。不能仅按“第四组”或文件夹顺序配对。

推荐按同一个采集编号组织，例如：

```text
data/
  export_00006.ply                同次同帧的合成 PLY
data_raw/
  export_00006/
    capture_info.json            配对信息，建议后续增加；当前工具尚不读取它
    1/                           第一路的 PLY、图片和参数
    2/
    ...
```

配对信息建议至少记录采集编号、导出帧号/时间戳、合成 PLY 路径及 SHA256、单位和标定版本；没有确认的字段写“未知”，不要根据近似外形自动认定对应关系。

如果还能取得深度图、深度有效性/置信度图、曝光参数、原始采集索引，建议一起保留，分别有助于后续几何融合和颜色一致性。本次导出的 36 张 PNG 都是彩色图，**没有独立深度图；相机 JSON 里有 IR 参数，不代表已经有了深度数据**。

原始采集容器或工程可留在服务器归档，不要求每次都复制到本机。存储紧张时，可归档完整 RAW，只解压当前处理的一帧；图片和配套参数应一起保留。

## 6. 当前已能运行什么，后面优先做什么

单 PLY 的日常入口仍是项目根目录下的：

```powershell
python run.py 3
```

1、2 号的配套 RAW 已验证，分别用 `python run.py 1`、`python run.py 2` 即可自动补色。RAW 补色采用 8 mm 邻域、法线余弦大于 0.7 和逐路投影检查。补色后的点色随正式 PLY、OBJ 导出。多视角补色生效时，外观阶段继续修正法线方向，并采用已核验的点色。可用 `--no-raw-color` 选择单 PLY 补色，或用 `--normals-only` 仅修正法线。

独立检查、对齐和补色也可运行：

```powershell
python tools/raw_capture.py "data_raw/采集编号/raw"
```

将示例中的目录替换为实际 RAW 路径。此命令用于检查和生成融合点云、报告及照片总览。按此目录示例，默认输出为 `outputs/capture_inputs/采集编号_frame00000/`。

| 文件 | 含义 |
| --- | --- |
| `aligned_original.ply` | 已对齐、保留原颜色的点云，尚无三角面 |
| `aligned_color_repaired.ply` | 同坐标的补色点云，尚无三角面 |
| `raw_report.json` | 输入文件、校验、投影和补色统计 |
| `images_overview.jpg` | 各路照片总览 |
| `color_comparison.jpg/json` | 使用额外的 `--mesh` 参数后生成的同网格颜色对比与统计 |

本轮试验网格曾保存于 `outputs/experiments/raw_capture/frame00000/`，存在孔洞，未通过可打印/封闭模型认证；该试验目录现已删除，原来的正式结果保留。RAW 处理脚本继续保留，下一批正确数据可复用。

1、2 号配套试验已复测补色效果。同网格对照中，1 号近纯黑顶点从 14,078 减至 1,004，2 号从 13,311 减至 841。后续可完善遮挡、颜色边缘和第二路照片的使用，减少下身遗漏。改善脸、手和其他部位的真实几何仍需要足够的几何观测。
