```text

```

只新增这一份持久文件。渲染图片、二维标签和推理临时报告在执行结束时自动清理；不生成额外的标签着色 PLY 或大概率数组。

## 记录内容

顶层包含 schema_version、status、coordinate_unit、mesh、method、parts 和运行来源。所有位置均为最终网格原坐标系下的毫米坐标，顺序为 `[x,y,z]`，没有另行居中或归一化。`mesh.sha256` 绑定导出的确切 PLY，顶点编号从 0 开始。

`parts` 按稳定英文名存储分割区域，例如：

- `left_hand` / `right_hand`：左右手。
- `left_lower_arm` / `right_lower_arm`：左右前臂。
- `left_upper_arm` / `right_upper_arm`：左右上臂。
- `face_neck`、`hair`：面颈与头发。
- `upper_clothing`、`lower_clothing`：上下身衣物。
- `left_shoe` / `right_shoe`：左右鞋。

其余名称和编号见文件的 class_map。这是模型的语义类别，不是人体骨架；穿着衣服的躯干或腿可能被标为衣物，不能强制解释为裸露的解剖部位。

每个区域包含：

| 字段 | 意义 |
|---|---|
| detected | 是否有通过保守筛选的顶点 |
| vertex_indices | 对应最终 PLY 的精确顶点编号，后续局部优化应优先用它 |
| vertex_count | 顶点数量 |
| center_mm | 被识别顶点的平均位置；不是关节中心 |
| bbox_mm.min / max | 被识别区域的轴对齐包围盒；不是完整手掌的真实边界 |
| vote_agreement_median | 多视角标签投票一致性；不是模型准确率 |
| minimum_supporting_views | 保留顶点的最少支持视角数 |

没识别到的部位仍保留条目，但 detected=false、vertex_indices=[]、center_mm=null、bbox_mm=null，不以零坐标假冒位置。遮挡和不确定顶点不属于任何保留区域，各部位顶点集合互不重叠。

## 后续读取手部范围

在项目根目录的 Python 代码中：

```python
import json
from pathlib import Path
import numpy as np
import open3d as o3d
from body_parts import load_part_indices

folder = Path("outputs/models/export_00001/本次时间")
position_file = folder / "body_parts.json"
info = json.loads(position_file.read_text(encoding="utf-8"))
left_hand = info["parts"]["left_hand"]

# 函数会校验状态、格式版本及当前 PLY 哈希，避免用旧标签修改新模型。
indices = load_part_indices(position_file, "left_hand")
mesh = o3d.io.read_triangle_mesh(str(folder / info["mesh"]["file"]))
hand_points = np.asarray(mesh.vertices)[indices]
center = left_hand["center_mm"]
box = left_hand["bbox_mm"]
```

将“本次时间”替换成实际目录。左右手位置可能贴近衣服，仅按包围盒选择所有顶点会混入裤子等表面，因此优化时应使用 vertex_indices。重新网格化、删点、改坐标、翻面或重新导出后，文件哈希可能变化，必须重新生成位置文件，不能直接复用编号。

## 运行与失败处理

- 默认复用本机 `D:\Anaconda\conda\envs\test0\python.exe` 进行 GPU 推理，主重建仍在当前环境执行，不安装或修改依赖。不同电脑可用 `--seg-python` 或 HUMAN_SEG_PYTHON 指定。
- 默认按明显最长坐标轴渲染为竖直方向，正向朝上。横放、倒置、坐姿等需要检查并使用 `--seg-axis`、`--up-sign` 指定；方向不明确时记录失败，不猜测位置。
- 权重、GPU Python、CUDA 或识别步骤失败时，body_parts.json 的 status 为 failed 并记录 reason，parts 为空；已经完成的 PLY/OBJ 保留，report.json 的 segmentation 字段也记录失败。`load_part_indices` 会拒绝失败文件。
- `--no-segmentation` 同时跳过识别和手部优化；`--no-hand-refine` 仅跳过手部优化。这些开关改变最终几何策略，会参与重建缓存匹配。
- 手部平滑不改变顶点编号与面连接。采用后标签沿原编号继承，中心、包围盒和模型哈希同步更新，geometry_update 字段记录来源。不会再次执行网络识别；再次运行相同命令会复用结果，不重复累积平滑。
- 分割结果有独立的模型哈希、权重、代码和配置缓存。结果缺失、失败或分割配置改变时可只补做分割；已完成的网格无需因此重新执行 Poisson。升级 run.py 本身后首次运行仍可能因原有代码指纹机制重建一次。
